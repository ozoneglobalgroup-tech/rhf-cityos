# RHF City OS — Operational Foundation v1.0-alpha

## ماهیت بسته

این بسته **سورس کامل یک برنامه عملیاتی تازه و مستقل** با پنل React، API مبتنی بر Node.js، PostgreSQL 17، گردش‌کارهای واقعی، نشست کاربری و کنترل محدوده داده با RLS است. اجرای آن در WSL با Docker Compose انجام می‌شود. این بسته **بازنویسی یا ادغام کامل `~/ruvos` موجود نیست**؛ چون فایل ۲۴۸ تایی سورس RUVOS در این گفتگو آپلود نشده است. نسخه قبلی `SourceKit` با این بسته جایگزین می‌شود.

### امکانات عملیاتی موجود
- راه‌اندازی با یک دستور، ایجاد رمز اولیه تصادفی، بدون نیاز به شناسه و داده واقعی از کاربر.
- تعریف هر تعداد شهرداری (در Tenant نصب‌شده) و ساختار سازمانی: معاونت، سازمان، اداره کل، منطقه، ناحیه، اکیپ و غیره؛ کنترل دامنه والد و شهر.
- کاتالوگ ۲۳ حوزه نرم‌افزاری خدمات شهری، قابل فعال‌سازی مستقل برای هر شهرداری.
- مدیریت کاربران و نقش شهری (SYSTEM_ADMIN، MUNICIPAL_ADMIN، DEPUTY، DIRECTOR، OPERATOR، AUDITOR، VIEWER).
- پرونده خدمات شهری: ثبت، اولویت، تخصیص واحد، وضعیت‌ها، الزام شواهد و پذیرش نهایی.
- مأموریت اجرایی وابسته به پرونده، ثبت شواهد انجام، ثبت تاریخچه.
- طرح خلق ارزش: خط مبنا، هدف، عملکرد، هزینه، سهم انتساب، منفعت خالص **فقط بعد از تأیید و ثبت شواهد**؛ شناسه یکتای منفعت برای پیشگیری از دوباره‌شماری.
- لاگ حسابرسی افزایشی؛ قطع ارتباط بین شهرداری‌ها با RLS + Scope سرور.
- داشبورد و میزکار فارسی RTL؛ تمام داده‌های عملیاتی از DB خوانده می‌شوند، نه از داده‌های نمایشی.

### قابلیت‌های هنوز پیاده‌سازی‌نشده
تمام ۲۳ حوزه دارای کاتالوگ و قابلیت ثبت پرونده/مأموریت/ارزش هستند، ولی **فرایندهای تخصصی کامل هر سازمان** (ناوگان، GIS، ۱۳۷، پیمانکاران، حسابداری، IoT، AI Agents و غیره) هنوز توسعه/اتصال نشده‌اند. این نسخه محصول عملیاتی پایه و قابل توسعه است، نه سیستم‌عامل جامع آماده بهره‌برداری سراسری. ارتباط با Keycloak و RUVOS اصلی هنوز انجام نشده است. نشست اولیه با حساب داخلی است، نه OIDC. استقرار اینترنتی/تولیدی بدون تست امنیتی، مدیریت تغییر، TLS، پشتیبان‌گیری دوره‌ای و آزمون بار مناسب نیست.

## نصب روی WSL

پیش‌نیاز: Docker Desktop/Engine فعال + Docker Compose، و وجود `unzip`, `python3`, `curl`.

```bash
ZIP="/mnt/c/Users/Hoosh/Downloads/RHF-CityOS-v1.0-Operational-Installer.zip"
unzip -tq "$ZIP"
mkdir -p /tmp/rhf-cityos-v1
unzip -oq "$ZIP" -d /tmp/rhf-cityos-v1
cd /tmp/rhf-cityos-v1/RHF-CityOS-v1.0-Operational-Installer
bash install.sh test
bash install.sh install
```

- آدرس بعد از موفقیت: `http://localhost:5189`
- نام کاربری و رمز اولیه فقط در فایل محلی `~/rhf-cityos-operational/credentials.txt` قرار می‌گیرد (`chmod 600`). **این فایل را ارسال نکنید.**
- فایل `.env` در همین مسیر با رمزهای تصادفی و `chmod 600` ساخته می‌شود. آن را منتشر نکنید.
- نام شهر اولیه «شهرداری شیراز» است و اطلاعات عملیاتی هیچ پرونده یا ارزش ساختگی ایجاد نمی‌شود. شهرهای دیگر را از داشبورد ایجاد کنید.
- این راه‌اندازی از پورت `5189` استفاده می‌کند و به RUVOS (5173/3000)، Keycloak و پایگاه داده قبلی متصل نمی‌شود.

## فرمان‌های مدیریت

```bash
cd ~/rhf-cityos-operational
bash install.sh status
bash install.sh logs
bash install.sh backup
bash install.sh stop
bash install.sh start
bash install.sh cleanup-list
bash install.sh cleanup-archive
```

`cleanup-list` فقط صفحات HTML مستقل قدیمیِ بالقوه بدون ارجاع را فهرست می‌کند. `cleanup-archive` تنها آن صفحات تأییدشده را به پوشه بایگانی قابل بازگشت می‌برد. **هیچ فایل پروژه اصلی، ماژول‌های React یا داده قدیمی حذف قطعی نمی‌شود.**

## نکات داده و امنیت
- دیتابیس اختصاصی `cityos` در Volume پایدار Docker حفظ می‌شود. `docker compose down` بدون `-v` دیتابیس را حذف نمی‌کند.
- نقش `cityos_runtime` با `NOSUPERUSER NOBYPASSRLS` و بدون مالکیت جداول ساخته می‌شود. GUCهای Tenant / Municipality / Actor در محدوده تراکنش تنظیم می‌شوند.
- `POSTGRES` اختصاصی به شبکه Docker محدود است و Port روی Host ندارد. UI روی `127.0.0.1:5189` منتشر می‌شود.
- نسخه فعلی ACL به سطح شهرداری و نقش محدود شده است؛ **کنترل دسترسی در سطح واحد سازمانی/ناحیه برای کاربر عملیاتی هنوز تکمیل نشده است**، لذا برای داده حساس بین سازمان‌ها مناسب نیست.
- قبل از استقرار عمومی باید رمزهای عبور قابل چرخش، قفل ورود ناموفق، OIDC/Keycloak، TLS و سخت‌سازی دقیق مجوزها کامل شود.

## ساختار سورس

```text
api/                 Backend Node.js، دسترسی Scoped و RLS
web/src/             رابط React، میزکار RTL
web/index.html       فقط قالب ورودی استاندارد Vite (نه صفحه HTML مستقل)
db/schema.sql        Schema، RLS و Grantهای نقش محدود
 db/catalog.sql      کاتالوگ ۲۳ حوزه خدمات
compose.yaml         Docker Compose شبکه داخلی و DB ماندگار
Dockerfile           Build پنل و API
install.sh           راه‌اندازی، پایش، Backup و توقف
tools/               بایگانی اختیاری صفحات اضافی قدیمی
tests/               آزمون‌های هسته دامنه
```

## معیار تحویل نسخه حاضر

تا وقتی `bash install.sh install` روی لپ‌تاپ اجرا نشده و Health Check و مرورگر بررسی نشده‌اند، راه‌اندازی روی دستگاه شما **تأییدشده نیست**. در محیط تهیه بسته فقط آزمون‌های منطق هسته و اعتبارسنجی ساختاری اجرا شده‌اند؛ Docker Engine و اتصال PostgreSQL در این محیط موجود نبوده تا E2E اجرا شود.
